# Admin UI (`components/admin/ui/`, `admin-header.tsx`)

(Root `CLAUDE.md` is git-ignored in this repo, so these notes live next to the code, like `components/hero/PITSTOP.md`.)

The admin follows the **same v2 rules as the public site**: sharp rectangles (no `rounded-*` except `rounded-none`), solid Title-case headings (no `uppercase`), `HoverFill` outline + fill hover, `IconButton` for icon-only controls, `ring-fg/70` focus. Don't hand-type button/field/card class strings: use the primitives.

- **Primitives** (`components/admin/ui/`): `Button` / `ButtonLink` (primary inverts on hover because the HoverFill rectangle is fg-coloured and would vanish on a solid fg button; secondary uses HoverFill; danger), `Field` + `Input` / `Textarea` / `Select` (one `fieldClass`; `Field` is a `<label>` wrapping label + control + hint + error), `Panel` (+ `inset`), `Tag` (sharp label: Draft/Hidden/Changed/New), `EmptyState`, `AdminHeading`, `MoveButtons` (up/down reorder: drag-and-drop doesn't work on touch), `DeleteButton`, `SaveStatus` + `useSaveStatus`, `StickyBar`.
- **Delete is two-step, never `confirm()`/`alert()`.** `DeleteButton`: trash `IconButton` turns into `Delete / Cancel` in place; Esc, Cancel or 4s reverts. Radio used to delete with no confirm at all.
- **Delete lives on the item's row in its list, never inside the item's own page.** Thoughts delete is on `/admin/blog` rows (`post-list.tsx`), collections on the `/admin/photos` rows, quotes/radio samples/triggers on their rows, photos on the photo rows of a collection page, portfolio entries on their rows in the editor; a post's editor and a collection's detail page have no delete. Row pattern when the row is also a link: the title `<Link>`'s `::after` stretches over the row and the `DeleteButton` sits in a `relative z-10` wrapper above it (a button can't nest in an `<a>`). A new list needs a delete here, not on its detail page.
- **Save feedback is one component.** Wrap every writer in `useSaveStatus().run(fn)`: it reports saving → saved / error with the reason, counts overlapping saves, treats a throw or a returned `{ error: string }` as failure, and resolves `{ ok, value }` (a void action still says `ok: true`). **A server action that reports failure by returning a plain string** (`updateCollection`, `updateRadioTrigger`, `createRadioTrigger`) is NOT recognised: throw it yourself inside `run` (see `collection-details.tsx`), otherwise the status says "Saved" over a rejected value. The status is the 4-state `SAVE_STATUS` machine in `lib/state-machines.ts` (written only through `move()`; `check:states` covers the forbidden edges and greps `use-save-status.ts` for raw writes).
- **Two save models, deliberately kept:** form pages (the portfolio blocks, thoughts editor) buffer edits and use `StickyBar` (sticks at the bottom of the page column, never `fixed left-0 right-0`, so it can't cover the nav or content); list pages (photos, quotes, radio) autosave on blur and show `SaveStatus` next to the field/row.
- **Danger colour is a token pair** (`--danger` + `--danger-rgb`, `colors.danger -> rgb(var(--danger-rgb) / <alpha-value>)`), same reason as `fg`: a bare hex var silently drops `text-danger/60`-style utilities. `check:colors` asserts the mapping, the dark baseline and ≥ 4.5:1 on both themes. Never reintroduce `red-500`/`green-500`.
- **Unsaved-changes guard** (`admin-header.tsx`): one capture-phase document click listener intercepts every same-origin link while `dirty` (nav, logo, BackButton, dashboard cards, View site) and shows a sharp banner (`Leave without saving` / `Stay`); logout and Publish use the same banner. `beforeunload` still covers tab close. It must stay a document-level capture listener: Next's `<Link>` handles clicks in React's root listener, which runs after it.
- **Navigation** is a top bar like the public header (`ADMIN_SECTIONS` in `sections.ts` feeds both the bar and the dashboard). The active link is a static `aria-current` ring, not the public nav's measured sliding marker (not worth the code here).
- **`.admin-scope` token overrides** in `app/globals.css` (brighter `--dim`/`--muted`, stronger borders) are intentional and stay.
- **Dev server needs a restart** after `tailwind.config.ts` changes (a new colour token compiled to nothing until then: the login error text rendered white).
- **Not verified in a browser:** everything behind `/admin` (needs the owner's session). Verified: `tsc`, `eslint app/admin components/admin`, `npm run build`, `check:colors/states/admin/botch`, grep gates (no `rounded-` other than `-none`, `red-500`, `uppercase`, `confirm(`, `alert(`, `fg/[0`, `border-fg/` in `app/admin` + `components/admin`), and the login page (error state) in headless Chromium.
- **Thoughts editor live preview** (`components/blog/post-preview.tsx`, toggle in `post-editor.tsx`): Write / Split / Preview (Split only at `lg+`; always opens in Write). Mirrors the public post's header + react-markdown overrides but **without `ScrollReveal`** (it would hide blocks until scrolled into the preview's own scroller) and with a plain `<img>` (public uses an async next/image). **The overrides are duplicated from `app/thoughts/[slug]/page.tsx`: change both together.** Links open in a new tab so the editor never navigates away from unsaved work; the body is `useDeferredValue`d so typing stays instant. Verified on a temp route in headless Chromium (since removed); the editor itself sits behind login and wasn't driven.
- **Portfolio is one block per page** (`/admin/portfolio` = index of cards with a one-line summary, `/admin/portfolio/<slug>` = one block + its own `StickyBar`). Blocks and the draft columns each owns live in `lib/admin/portfolio-sections.ts`. **Saves go through `updatePortfolioSection(slug, patch)`, which writes only that block's columns** (whitelisted server-side): the old whole-object `updatePortfolio` would let a stale open tab overwrite a block saved elsewhere. `updatePortfolio` is now unused by the admin. The unsaved-changes banner is per page; the changed-sections popover is gone (it only ever has one block). Not driven in a browser (login required).
- **Post slug rename** (`renamePost` in `lib/admin/actions.ts`, field in `post-editor.tsx`): saves on blur as its own action (writes only the slug column, so unsaved edits survive) and swaps the URL with `history.replaceState`, **not** `router.replace`: a new `[slug]` param remounts the editor and drops unsaved edits. The editor therefore reads the live `fields.slug`, never the `slug` prop (which is the initial value only). New posts have no slug field (the slug is chosen when the post is created). Old `/thoughts/<old>` links stop working once published (no redirect is kept). `useSaveStatus.run` now resolves `{ ok: false, error }` so callers can show the reason.
- **Layout edges.** The admin `<main>` is `max-w-6xl px-6`, the same container as the header, so the logo, back button, headings and panels share one left edge (pages inside it are `max-w-5xl`, left-aligned). Use `AdminBackLink` (`ui/back-link.tsx`), **not** the public `BackButton`: that one hangs in the gutter and assumes a centred column, so inside a left-aligned column it lands 40px too far left. Header controls (View site, theme, Publish, Log out) are all 48px tall; Button text is `whitespace-nowrap` there (Log out wrapped to two lines at 390px). A live region that sits between spaced siblings (`SaveStatus` wrappers) is `sr-only` while idle so it doesn't leave a permanent gap but stays mounted for screen readers.
- **`Select` width.** `fieldClass` has `w-full`; a `w-auto` passed via className loses to it, so use `!w-auto`.
- **How the admin was reviewed without a login:** a throwaway page rendered the real components with fake props (no auth, no DB) wrapped in `admin-scope`, shot with Playwright at 1440 and 390 in dark and light. It was deleted afterwards; rebuild it the same way for visual review (mock data: collections, photos, posts, quotes, samples, triggers, portfolio blocks).

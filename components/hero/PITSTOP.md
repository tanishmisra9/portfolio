# Hero pitstop (`use-pitstop.ts`, `scatter-name.tsx`, `hero.tsx`)

(Root `CLAUDE.md` is git-ignored in this repo, so these notes live next to the code. Merge into `CLAUDE.md` if wanted.)

Clicking the name runs a pit stop with **4 tires** (TL `TAN`, TR `ISH`, BL `MIS`, BR `RA`), not 11 letters: tires fly toward their own corner → snap back one by one → the whole name slides off right → re-enters from the left (as if the page wraps around). Phases are `HERO_PHASE` (`lib/state-machines.ts`, tested by `npm run check:states`); clicks are ignored unless `idle`. Letters stay separate spans only for the cursor magnet; the pit-stop offset lives on the two group spans each `ScatterName` renders. There is **no blur or opacity animation** any more (a blur-fade-in was tried and rejected by the user; the old version also kept `blur(0px)` layers on all 11 letters): the drive wrapper in `hero.tsx` only animates `x`.

- **One sound, one timeline.** `public/sfx/pitstop.mp3` (4.46s) = silence 0–0.9s (the split is silent on purpose, and the silence keeps `play()` inside the click gesture) → **wheel-gun burst 0.9–1.61s** (the "pit stop" sound, played as the tires rejoin; one continuous burst, not 4 hits) → gap → **engine growl 1.76–2.96s** → **drive-off 2.96–4.46s, engine rev peaks ~3.85s**. `LAUNCH_MS` / `BOLT_MS` / `DRIVE_MS` in `use-pitstop.ts` are the tuning knobs; **re-measure if the clip is re-cut.** Snaps *land* (start + ~120ms flight) inside the gun burst; the drive-off is a soft easeInCubic (0.55s) that is moving fast as the rev peaks; then a 0.35s pause (`ENTER_PAUSE_MS`) off-screen and a 0.3s easeOut re-entry from the left (`ENTER_S`). The timeline anchors to the audio's `playing` event (a slow first load can't desync the snaps); if `play()` is rejected it runs silently from the click. `play()` is called synchronously in the click handler (iOS gesture rule: assumed, not tested on a device).
- **Lesson: identify the sounds before timing them.** The first three timings were wrong because the clip was cut from spectrogram analysis alone and the roles were mislabelled: the source's 7.3–8.4s block is the car's engine *growl*, not gun noise, and the real pit-stop gun burst (source 5.95–6.66s) had been placed at the split, then cut entirely. Only the user's ears settled it. If the clip changes, have the user confirm what each section is before tuning times. Cut points are from the first of two stops in the Short: gun burst 5.95–6.66, growl 7.26–8.46, drive-off 8.46–9.96.
- **Audio latency offset.** The `playing` event fires *before* sound reaches the speakers, so the picture ran early. `SOUND_LATENCY_MS` (200, a first guess, not measured) delays every visual; `?pitstopOffset=<ms>` overrides it per device (try 100–400, higher for Bluetooth) to find the right value, then bake it into the constant. Launch times are click-relative, everything else anchors to `playing`.
- **Clip source and cleanup.** Cut from a YouTube Short (2 stops in 20s; the first was used). Bursts are ~20 dB above the floor in the 1.5 kHz+ band, so a 450 Hz highpass + `afftdn` removes the low-end crowd/BGM bed. A stem separator can't do this job (the Higgsfield tool splits vocals vs. rest, so gun noise stays bundled with the music). Build the clip from separate `-ss/-t` segments and concat: one `filter_complex` with `atrim` + `afftdn` produced a mostly digitally-silent file with no error. Re-verify any new cut with `silencedetect` on the decoded output, not the envelope of the mp3.
- **Magnet cost.** `pointermove` is rAF-throttled and skipped while the phase isn't `idle` (each pass reads every letter's rect).
- **Verify.** `npm run check:states` (confirmed failing with a raw `phaseRef.current =` write and with an extra edge), then drive the real page with `playwright-cli run-code --filename`: `click({ force: true })` is required because the idle drift in `HeroNameMotion` never lets Playwright's stability check pass. Measured on desktop: tires gone by ~160ms, near home at ≈ anchor + `BOLT_MS` + ~160ms spring, slide at ≈ anchor + `DRIVE_MS` (+ latency offset), re-entry from ≈ −1.15×viewport settling at 0, opacity always 1 and zero blurred elements, one `play()` per run even with a second click mid-run.
- **Effect deps must stay stable** in `usePitstop`: the cleanup flags the run dead, so a re-run mid-stop would strand the phase and leave clicks dead until reload.

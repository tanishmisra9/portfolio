# Hero pitstop (`use-pitstop.ts`, `scatter-name.tsx`, `hero.tsx`)

(Root `CLAUDE.md` is git-ignored in this repo, so these notes live next to the code. Merge into `CLAUDE.md` if wanted.)

Clicking the name runs a pit stop with **4 tires** (TL `TAN`, TR `ISH`, BL `MIS`, BR `RA`), not 11 letters: tires fly toward their own corner → snap back one by one → the whole name slides off right → blur-fades back in. Phases are `HERO_PHASE` (`lib/state-machines.ts`, tested by `npm run check:states`); clicks are ignored unless `idle`. Letters stay separate spans only for the cursor magnet; the pit-stop offset lives on the two group spans each `ScatterName` renders. The **only blur** is one `filter` on the drive wrapper in `hero.tsx` during fade-in (it is `none` at rest; the old version kept `blur(0px)` layers on all 11 letters).

- **One sound, one timeline.** `public/sfx/pitstop.mp3` (3.46s) = guns-off burst 0.03–0.71s (plays during the launch) → guns-on whine 0.79–1.96s → drive-off 1.99–3.46s. `BOLT_MS` / `DRIVE_MS` in `use-pitstop.ts` are measured from that clip and are the tuning knobs; **re-measure if the clip is re-cut.** The whine is one continuous sound, not 4 hits, so the 4 snaps are spread across it. The timeline anchors to the audio's `playing` event (a slow first load can't desync the snaps); if `play()` is rejected it runs silently from the click. `play()` is called synchronously in the click handler (iOS gesture rule: assumed, not tested on a device). The cut points and the knob values were chosen from waveform/spectrogram analysis, not by ear.
- **Clip source and cleanup.** Cut from a YouTube Short (2 stops in 20s; the first was used). Bursts are ~20 dB above the floor in the 1.5 kHz+ band, so a 450 Hz highpass + `afftdn` removes the low-end crowd/BGM bed. A stem separator can't do this job (the Higgsfield tool splits vocals vs. rest, so gun noise stays bundled with the music). Build the clip from separate `-ss/-t` segments and concat: one `filter_complex` with `atrim` + `afftdn` produced a mostly digitally-silent file with no error. Re-verify any new cut with `silencedetect` on the decoded output, not the envelope of the mp3.
- **Magnet cost.** `pointermove` is rAF-throttled and skipped while the phase isn't `idle` (each pass reads every letter's rect).
- **Verify.** `npm run check:states` (confirmed failing with a raw `phaseRef.current =` write and with an extra edge), then drive the real page with `playwright-cli run-code --filename`: `click({ force: true })` is required because the idle drift in `HeroNameMotion` never lets Playwright's stability check pass. Measured on desktop: tires gone by ~160ms, near home at ≈ anchor + `BOLT_MS` + ~160ms spring, slide at ≈ anchor + `DRIVE_MS`, one blurred element max, one `play()` per run even with a second click mid-run.
- **Effect deps must stay stable** in `usePitstop`: the cleanup flags the run dead, so a re-run mid-stop would strand the phase and leave clicks dead until reload.
